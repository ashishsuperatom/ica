# UI review — user UI, admin console, templates, design system (2026-10-10)

A read-only review of `control-plane/user-ui`, `control-plane/superadmin`, `vm/packages/project-template` (agent and
dashboard templates) and the shared kit `vm/packages/ui`, against the standing UI rules (design system owns layout, no
shadows, nothing jumps, compact words, typed state, progressive disclosure, users never see internals). Nothing was
changed by the review. File:line references are as of commit 83ffa2e0.

## The patterns behind most findings

1. **The kit is missing a few primitives, so every screen improvises them.** No `Button` (~370 hand-strung `sa-btn`
   class strings; one, `sa-btn--secondary`, doesn't exist), no confirm/copy dialog in the kit (five confirmation styles:
   `confirm()`, `alert()`, two type-the-name variants, none at all for some removals), no loading line (loading drawn
   six ways), no shared date/`ago`/bytes formatters (~10 date helpers, 41 raw `toLocale*` in admin), no `StartCard`, no
   History/Versions components (their CSS sits in shared `semantic.css` for single admin screens).
2. **Duplicates.** Two empty-state components (`Empty`, `Nothing`), three key/value idioms (`Receipt`, hand `sa-dl`,
   hand `sa-facts`), two pagers, two status vocabularies both named `State`, the dashboard template's own copies of
   AskBar/Controls/FilterAdd/WindowControl beside the kit's, three near-identical agent terminal pages in admin, Activity
   built twice in the user UI, markdown-stripping written four times.
3. **Internals reach users.** Raw `reason`/`error` strings in user-UI toasts and notices (`Workspace.tsx:137,203,307,463`,
   `pageBlocks.tsx:87,118,191,231,288,335`), program exceptions, and engine jargon ("on the engine", "A node of the
   knowledge graph: owned, versioned, governed").
4. **Things jump / false states.** "No agents you can see yet" and "0 connections" before the data arrives
   (`pageBlocks.tsx:75,90,193`); failed fetches swallowed so a list shows its skeleton forever (`pageBlocks.tsx:187,286`);
   admin figures with no loading state (`Billing.tsx:33`, `App.tsx:1494`); the agent template view returns `null` while
   loading.
5. **Lists not searchable/paged.** `RecordList` supports both; the user UI uses neither anywhere; admin uses them on five
   lists (event log, people, access, keys, credentials don't).
6. **Captions repeating headings** — page title then a section of the same title (Engine version, Audit history,
   Dashboards, Groups, Event log, the three terminal pages).
7. **Untyped state.** ~1,045 `any` in superadmin (54 in `App.tsx`), `useState<any>` in both apps — the pattern that has
   shipped crashes twice.
8. **`App.tsx` (1,760 lines) carries ~250 lines of dead code** (old sidebar CSS with hard-coded `#fff`, unused icons,
   `ProjectCardButton`, unreachable org tabs/user/key-rotation code) and whole panels that belong in their own files.

## Information architecture (where things live)

- **Admin project home is the Engine page, not Attention** (`App.tsx:405`).
- **Operations has 12 places:** Engine contents / Files / Database / Logs are one Engine page with tabs; three logs (Event
  log, Audit history, Logs) need one guide or one place; Dashboards is not operations.
- **Misplaced:** organisation keys inside the Warehouse explorer (belongs under People and roles); email-domain sign-in
  inside Data access (belongs under Access and roles); two Teams credential paths (Settings and Channels).
- **Names that don't match:** "Addresses" place titled "Subdomains"; "Models and agents" page titled "Agents"; the
  project "Warehouse" place is the explorer over every source; Questions/Sessions under Knowledge are activity.
- **User UI:** agents listed in five places; Activity, Agents, Connections each reachable three ways (and Activity has two
  different views); the Home sidebar puts map sections above the person's own conversations; a connection page shows
  test + reads + actions + the full call log at once (the log should be collapsed).

## Templates

- The agent template teaches against the contract: totals summed in JS over unbounded rows (`server/index.ts:19`,
  `query.ts:4`) instead of in the source query with a 100-row limit; a row click narrows in place (`server/index.ts:7`)
  where the contract says it opens a new block; the view renders `null` while loading.
- Two dashboard models coexist: agents with program views (the contract) and the standalone template app with its own
  runtime and kit copies (`docs/features.md:127` claims it draws from the kit — it partly copies it).
- Two scaffolders (`sacli agent init`, `programs init`) behave differently.

## Ranked fixes (across all surfaces)

1. **Fix the confirmed bugs 1–6 above**, and add the template app tsc + `programs build` of the agent template to
   `scripts/check-all.sh` so templates can't silently break again.
2. **Users never see internals:** one plain user-facing message for failures in user-UI toasts/notices and the program
   loader; reasons go to the console/operators (`Notice` replaces `sa-program-error`).
3. **No false or endless states:** pass `loading` until data arrives (no "0 …"/"No agents" before it); a failed fetch
   becomes `[]` + an error `Notice`; loading states for admin figures.
4. **Kit primitives:** `Button` (primary/secondary/link/danger/pill), `ConfirmDialog` + `CopyButton` (move from
   `App.tsx`), a `Loading` line, `dateTime`/`ago`/`bytes` in `lib/format.ts`; then replace the copies.
5. **Search + paging** on every growing list (user UI activity/agents/connections/archived; admin event log, people,
   access, keys, credentials); Groups and Dashboards as a list with a detail view.
6. **Admin IA:** open projects on Attention; one Engine page with tabs; move org keys and email domains under People;
   one Teams credential path; names matching their pages.
7. **Remove repeated headings** on the pages listed above.
8. **Delete dead code and split `App.tsx`** (DataSources, Channels, AgentProfile, ProjectSettings, OrgPages); type the
   `status`/`orgs`/`projects` state; one `AgentTerminal` for the three terminal pages.
9. **Merge duplicates in the kit:** `Nothing` → `Empty`; key/value idioms → `Receipt`; one status vocabulary; one pager;
   move domain cases (INR lakh/crore, A$, people/projects units) out of `format.ts` into project formats.
10. **Templates:** the agent template computes totals in SQL with a limit, opens a new block on row click, draws a
    skeleton; decide whether the standalone dashboard app is retired in favour of agent programs (then delete its kit
    copies); one scaffolder.

Smaller: one icon set (lucide 257 / solar 49 / mdi 7 in use), status words in one case, sign-in screens on tokens (they
hard-code `#8a8276`/`system-ui`), the `sa-card--lift` name dropped (nothing lifts, but the name invites it), raw font
sizes/radii and the `#14b8a6` gradient as tokens, one spelling ("organisation").
